# Traefik runbook (dmon k3s cluster)\n\n## What traefik is here\nk3s-bundled Traefik (currently 3.x, chart-managed) in `kube-system`,\ncustomized via a `HelmChartConfig` named `traefik` (failurePolicy:\nreinstall). The pod currently schedules on **robo-dog**; `svclb-traefik`\nDaemonSet pods on both nodes give the LoadBalancer service its node IPs.\n\n- Service: `kube-system/traefik`, LoadBalancer, EXTERNAL-IP 100.92.111.3\n  (tailnet), ports 80:32668 and 443:31291.\n- What it serves:\n  - Ingress `nexus/dashboard` — `dashboard.nexus.carriedworld.dev` →\n    service `nexus-broker:7888` (the nexus-control pod), via\n    ServersTransport `nexus/nexus-broker-upstream` (HTTPS upstream).\n  - IngressRouteTCP `cwb/core-edge-*` (almanac, atlas, commonplace,\n    custodian, ledger, mason, porter-backup) — TCP passthrough edges for\n    the CWB gRPC/mTLS services.\n- Certificates: ACME (Let's Encrypt prod) via the `cloudflare` resolver,\n  DNS-01 with `CF_DNS_API_TOKEN` from secret `cloudflare-dns-token`.\n  Domains: core.carriedworld.dev + *.core, nexus.carriedworld.dev +\n  *.nexus. acme.json persists on a 128Mi local-path PVC — this MUST stay\n  persistent (LE rate limit: 5 duplicate certs/week). An init container\n  creates/chmods /data/acme.json to 0600 (traefik refuses to start\n  otherwise).\n\n## Health checks\n    sudo k3s kubectl get pods -n kube-system -l app.kubernetes.io/name=traefik\n    sudo k3s kubectl get svc -n kube-system traefik          # EXTERNAL-IP present?\n    sudo k3s kubectl logs -n kube-system deploy/traefik --tail=50\n    curl -skI https://dashboard.nexus.carriedworld.dev        # end-to-end\nHealthy logs show a daily \"Testing certificate renew...\" INF line\n(cloudflare.acme) around 01:45 UTC. The \"new release of Traefik found\"\nWRN is noise.\n\n## Common failures\n1. Cert path: renewals fail → check the acme lines in the log, the\n   `cloudflare-dns-token` secret, and that the PVC (acme.json) is\n   mounted. If acme.json was lost, expect a full re-issue — watch LE\n   rate limits, and consider the staging caServer (commented in the\n   HelmChartConfig) to prove the DNS-01 flow first.\n2. Ingress/upstream path: `error building proxy ... servers transport\n   not found nexus-nexus-broker-upstream@kubernetescrd` appears when the\n   ServersTransport CRD object is missing/recreated after traefik boots\n   (last seen 2026-08-02; the object exists now). Fix: ensure\n   `serverstransport nexus-broker-upstream` exists in ns `nexus`, then\n   restart traefik so it rebuilds routers.\n3. Config not taking effect: `ports.websecure.tls.*` values silently do\n   NOT render in the k3s-bundled chart — entrypoint TLS settings must go\n   through `additionalArguments` (already done; keep it that way).\n\n## Restart procedure\n    sudo k3s kubectl rollout restart -n kube-system deploy/traefik\n    sudo k3s kubectl rollout status  -n kube-system deploy/traefik\nConfig changes go in the HelmChartConfig (`kube-system/traefik`); k3s's\nhelm controller re-renders and reinstalls automatically on edit. Nuclear\noption (chart re-render without config change): delete the traefik pod;\nthe acme PVC keeps certs. Never delete the PVC.\n
